# 山门 Demo2.0 有限基础补给规则

基础补给用于正式探索死亡后重新出发，不是重新初始化人物，也不是免费商店。当前增量已接入整备按钮和同一物品事务；正式探索玩家路径尚未接通，因此石庭练习死亡不能触发这项补给。各项运行证据以本轮 Report 与 Development Log 为准。

## 发放条件与内容

物品权威必须持有最近一次同 Owner、同整备作用域的成功 Death 终局回执。该死亡之后不能已经准备或开始下一局。没有正式死亡、存在待提交资源预留、作用域不匹配、过期状态，均拒绝，不修改数量。

| 检查对象 | 确实缺失时补给 | 发放位置 |
| --- | --- | --- |
| 任意已拥有武器 | 青锋剑 1 把 | 武器槽 |
| 任意已拥有护具 | 素纹道袍 1 件 | 护具槽 |
| 任意已拥有普通背包装备 | 基础行囊 1 个 | 背包装备槽 |
| 任意已拥有回春丹 | 回春丹 2 枚 | 局外仓库合法空位 |

检查整个 Owner 的现存物品，不只检查装备槽或基础定义。仓库里的玄铁剑、护身皮甲与扩容行囊同样算已经拥有；卸下、移动、拆分或关闭面板不能把物品变成“缺失”。已有 1 枚丹药也不补到 2 枚。储物装备仍禁止嵌套。

不发灵石、不补高级装备、不发材料或战利品、不重发护命匣、不重置新档配置。补给后的基础行囊启用 6×4 普通背包；有替代行囊在仓库时不额外发小包，玩家需手动装备仓库行囊。

## 有限领取与失败关闭

每个已确认死亡最多执行一次非空补给。申请和新物品身份均由 Owner、整备作用域及死亡身份确定性派生；同一申请在重复点击、重开或重启后返回原回执，不再次发放。换请求 GUID 不合法，换政策也不能绕过同一死亡的领取限制。全套已有时拒绝且不消耗机会。

检查缺失、放置新物品、调整背包容量、记录领取回执在一个候选中完成，由既有服务一次原子发布。后续行放不下或政策不合法会丢弃整个候选，不先发部分装备。发布失败沿用现有回滚／重开协议；未确认持久状态时 UI 不能报告领取成功。

本规则要求固定政策来自产品代码，不接受 UI 自定义定义、数量或目的容器。UI 只点击领取，GameMode 读取权威快照生成当前政策，Subsystem 与 AuthorityService 仍是唯一写入链。没有第二份库存或补给次数文件。

## 与死亡和后续开发的关系

终局销毁背包装备时，同一次提交还要把空普通背包变为禁用容量。存在未处理内容时终局拒绝，不通过删除内容来满足容量校验。安全格的玩家终局筛选仍需正式探索接线；本轮不把未投入 Run 的安全格物品保留测试当作完整死亡保留验收。

下一步仍是正式 Run 出发、携带筛选、治疗、随机来源搜集和终局恢复。这项有限事务不替代实际键鼠死亡后的完整领取、整备和再次出发验收。
