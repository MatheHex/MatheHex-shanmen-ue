# Demo2.0 结算明细人工审查

本增量只由代理编写、构建和无头验证，不接管游戏窗口。普通丹药“正常使用”的人工反馈属于此前主路径，不代替这里的结算、混合堆与重启检查。完整 [探索 Goal](../Prompt/Demo20.Expedition.goal.md) 仍在开发。

## 打开与安全

使用新候选 DLL，先退出其他 UE 进程；不要在旧窗口里测试新代码。正常启动入口：

```powershell
./Scripts/Start-Demo20.ps1 -Action Play -ProfileName ManualSettlement01 -Width 1280 -Height 720
```

这是新的隔离验收档，未要求删除已有档。需要重复同档检查时保留档名；1080p 使用 `-Width 1920 -Height 1080`。不使用控制台发物、降血或改存档，不拿石庭练习当正式结算。不要求主动损坏真实档；保存故障已有隔离原生测试，画面故障提示仍待安全人工场景。

## 撤离页

整备后进入青岚关。在安全位置搜寻宝匣，只看不拿的一堆记为对照；选取一部分同类物品，观察实际部分合并量及来源余量。不要假定随机一定给药或指定战利品。受伤、退到安全处，松开格挡并等动作恢复后用一颗丹药，记下实际扣药数。战斗实时操作由人完成。

记录所取、所用以及终局前普通／安全格和装备数量。返回归阵，正常三秒撤离；页面确认保存后应列：

- 搜寻取得：从宝匣／守卫遗物实际转入普通背包／安全格的累计数量，部分合并只计转入量，不计生成、预览或未领取余量。
- 本局消耗：已提交的物品数量消费；出发时锁定／接管携带不算用掉，失败或重复请求不算新的消费。
- 已带回：终局时实际携带、装备和安全格的物品，包含出发就带入的物资，不称作全是本局新奖励。
- 场景遗留：本局已落实场景容器的剩余，包括搜索后没拿的物品和未取回的玩家丢弃，不计为带回，也不把全数说成玩家曾经取得后损失。未搜索、未落实的潜在掉落不猜测、不列入数量。

取得是操作累计，不是每单位去重的来源追踪。丢到地面再取回不增加取得；若主动放回搜寻容器再取出，会再次计入取出操作，但不生成新物品。界面应有说明；不将这一数值当作额外奖励。

## 死亡页与下一局

在安全处先记普通背包、装备、安全格数量。主动从安全格丢到地面且没有取回的物品不再受安全格保护。按正常战斗过程死亡，确认保存后检查：普通携带与装备列“死亡损失”，安全格和护命匣列“死亡保留”，局外仓库只说明保持，不把整个仓库当本局奖励。场景遗留单独列。

明细必须保留死亡前数量，不能因为实际实例被清零就显示零损失。返回整备后核对实际仓库／安全格；有限补给不应改写上一局的历史损失。穿戴备用或缺失补给、装药后再次正常出发，不重发初始灵石。

## 重启、滚动与确认状态

在结算页确认保存后关闭窗口，重开同一个隔离档。在整备页点击“查看最近结算”：该终局历史的数量与中文名称保持，不根据现在的仓库重算。返回整备、重开明细或重复点击不重新执行终局、不重复发奖或扣药。该入口是最近一份完整且已保存的物品统计；不是正在进行的新局，不重新加载已结束世界。

旧版本已开始的局没有完整统计事实，应明确提示“旧版本局／记录不可用”，不能填一份猜出的零统计；仍应正常完成原局结算。之后新局才从完整起点记录。

在 720p 和 1080p 检查长物品列表：正文可滚动，主要“返回仓库与整备／重试确认结算”按钮在固定位置可见，滚动不触发移动或攻击。最近结算中按 Esc 或“返回整备”应关闭只读明细，不出发、不结算；切换界面正文回到顶部。保存未确认时不展示成功数量，不可绕过确认返回；记录提示文字和日志，不删档解决。

反馈请包括候选版本、档名、分辨率、撤离或死亡、用药前后与终局前数量、结算显示、重启后是否一致、按钮／滚动／焦点情况；有失败可附截图与日志。缺少实时或画面证明的项目保持待验收，其他独立开发照常推进。
