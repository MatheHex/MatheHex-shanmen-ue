# Demo2.0 携带与正式探索权威边界

本页记录整备格子进入正式探索时的当前契约，供后续关卡、背包、治疗与恢复接线复用。它不是探索 Demo 完成证明。石庭练习仍不结算，不能调用正式出发事务来伪装探索完成。

## 携带筛选

出发条件为已装备武器、护具和普通背包。治疗物资可以由玩家自行选择携带，不强制携带丹药。当前物品目录只有固定属性；本增量不调整战斗数值。

| 整备位置 | 出发事务 | 当前终局行为 | 后续局内访问 |
| --- | --- | --- | --- |
| 武器、护具、普通背包装备 | DeploymentLock 预留后启动 | 死亡损失，撤离释放锁并保留原身份 | 由 Run 回执读取，不直接改装备 |
| 普通背包物资 | 整堆 Quantity 预留后启动 | 死亡损失，撤离只返还未消耗余额 | 余额从启动与消耗回执重建 |
| 普通背包中的备用装备 | DeploymentLock，仍属于普通携带 | 同普通损失规则 | 不能用 UI 另存数量 |
| 安全格装备与内容 | 留在唯一物品文档，不加入普通损失清单 | 已确认内容和装备保留 | 局内移动、丢弃与使用端口尚待接通 |
| 局外仓库与测试钱包 | 不进入携带清单 | 保持原数量、身份和位置 | 探索期间不得通过整备 EditGrid 修改 |

这不是免除安全格消耗：后续使用仍必须通过 Run 专用权威命令确认扣除。从安全格主动丢弃后的归属也必须先持久确认，不能继续套用“安全保留”。当前局内安全格操作未开放。

## 原子出发

产品层 `FShanmenDemo20Loadout::Build` 读取权威快照，筛选普通携带并按物品身份排序。出发意图固定 Owner、准备 Scope、内容戳、权威版本、每件物品版本、资源类型、数量与原位置。请求身份从准备版本确定性派生；UI 打开次数和数组顺序不参与。

既有 Subsystem 的 `StartLoadoutDurable` 调用同一 AuthorityService。一个锁覆盖候选预留、已有 `StartPreparedRun` 和保存。中间预留只存在于候选 Repository；任何行拒绝、Run 冲突或可确认回滚的保存失败都不能发布半成品。接受后新增一个存档代次；审计中保留每行 Reserve 和 StartPreparedRun 回执，因此权威版本可以推进多次，但磁盘不逐行写入。

公共入口不引入新事务枚举、第二份库存或新存档格式，继续使用 schema 6。新批次不能接管其他路径创建的预留，也不能把未完成预留遗留在正式 Run 后面。拒绝不插入批次失败账本；调用日志保留原因，权威快照保持不变。

精确重试需要原冻结意图。即使启动回执存在，也必须逐行校验 Reserve 指纹；改数量、用途、物品版本、Owner 或身份不能借同一批次重放成功。重建下一局时使用终局保存后的新权威版本和新的启动身份。

## 只读恢复投影

`InspectActive` 从已有启动回执识别唯一未结算正式 Run，核对 Demo2.0 携带用途与 Owner／Scope。Quantity 余额由预留总数减去已确认的直接消耗和已提交 Quantity Intent 得到；已取消 Intent 不扣除。存在尚未完成的 Quantity 或资源 Intent 时返回恢复原因，不把未知结果当作免费使用。

每个正式 Run 的 64 位 RunSeed 从持久 RunId 和固定种子命名空间派生。它不依赖进程随机流、帧数或 UI 交互，也没有第二份种子文件。后续随机来源须带固定内容版本和稳定来源身份；本增量未生成敌人、宝箱或掉落计划。

投影不保存数量。它尚不恢复生命、位置、敌人、搜索或世界对象，不能称为完整原局恢复；后续产品恢复应组合这些契约，不重抽已接纳来源。

## 整备与局内命令分区

准备 EditGrid 在同一 Owner 有未结算 Run 时拒绝，包括仍处于 Stored 的安全格、仓库物品。不能因为它们没有普通部署锁，就在后台把它们移进普通背包、换储物装备或绕过死亡规则。终局确认后解除该准备限制。

局内二维背包、部分领取、丢弃、拾回与安全格使用必须有独立的 Run 上下文校验，但仍调用现有物品权威。不要打开准备 EditGrid 的漏洞，也不要恢复 Code A／Code B 库存 writer。当前新的出发端口只在隔离自动化中验证；玩家按钮暂不启动正式 Run，避免在缺少地图与世界恢复时锁住测试档。

## 接线顺序

下一增量应建立新的固定探索区域与正式出发、返回的产品入口，并接通支持继续游戏的世界状态持久化；启动成功后再生成表现。然后实现局内治疗与携带投影、安全格操作、稳定来源接纳、搜索和转移。需要同时证明真实键鼠行为、保存失败提示、退出续局，以及撤离／死亡后的再次出发。

整备携带预览在快照刷新时计算并缓存，不在每次 Paint 中创建 Repository 或遍历历史账本。出发候选仍包含权威状态复制，最多接受 256 行；其真实运行内存、耗时及多轮对象释放必须在 M5 测量，不能用 JSON 字节数或上限估算替代实测。
