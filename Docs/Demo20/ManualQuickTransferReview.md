# Demo2.0 背包便捷领取人工检查

检查双击、部分领取和整理是否与实际游戏一致。新代码已通过 Editor 编译及本页三项原生测试，完整文件映射与最终 Game 结果见本阶段 Report／Log；本文不是人工已通过证明。只用隔离测试档，通过正常界面搜集，不改存档、不调试发物，代理不接管游戏窗口。

## 便捷领取与取舍

1. 在安全位置搜索宝箱或敌人遗物。记下来源物品数量和背包同类堆叠数量；双击来源物品一次，或选中后点“移入普通背包”。
2. 若背包已有兼容未满堆叠，应先合并。来源多于该堆叠剩余容量时，只取能合并的部分，其余仍显示在原处；提示应与实际增减一致。例如 8+3、上限 10，应变为背包 10、来源 1。
3. 第二次独立操作才尝试领取余量。没有空格也没有未满堆叠时，应拒绝并保留来源。不要因为没出现该随机物品组合而用控制台造条件；可先验证本次实际出现的组合。
4. 通过正常搜集填满格子后，若仍有未满堆叠，便捷操作应能合并。只有横向空位的长条物品应尝试旋转；手动旋转和拖放仍可使用。

## 输入与持久结果

双击不应触发世界攻击或残留拖拽。点击已在普通背包内的物品，应提示直接拖动整理，不自动移入安全格、地面或仓库。关闭再打开来源，数量不回涨；正常暂停退出并重启后，已确认领取状态应保留。

局内背包和搜索不暂停世界，先清理附近危险；Esc 暂停才暂停单机。不需要在攻击中冒险拖放。检查 1280×720 和 1920×1080 的按钮、余量提示、鼠标捕获和返回焦点。记录实际物品名称、来源前后数量、背包前后数量、提示和分辨率；若有异常，保留该隔离档并反馈，不继续在异常路径叠加操作。

存盘失败不要求人工破坏档案制造条件，失败与幂等数量由隔离原生测试证明；实际失败提示仍需后续专用 fixture 可见核验。测试断言和双目标编译不能替代本页的实际双击／画面检查。结果及版本范围见 [便捷领取 Report](../Report/Demo20.M5.QuickTransfer.r0_report.md) 与 [Development Log](../Log/Demo20.M5.QuickTransfer.r0_log.md)。
