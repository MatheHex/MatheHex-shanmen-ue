# 山门 Demo2.0 原携带物统一背包人工审查

本说明检查出发时携带的物品与新战利品是否使用同一个实际背包。对应 [统一背包 Report](../Report/Demo20.M3.RunInventory.r0_report.md)。既有普通丹药人工反馈保留；本增量整理、治疗恢复和组合终局尚无实际窗口证据。代理不接管游戏窗口，人工审查可以稍后进行，独立开发继续。

## 版本与隔离档

使用 Report 对应的已编译基线。先正常退出自己的旧游戏或 Editor，避免旧 DLL 驻留；不删档、不搬档，不覆盖真实存档。项目目录运行：

```powershell
./Scripts/Start-Demo20.ps1 -Action Play -ProfileName ManualRunInventory_20261005 -Width 1280 -Height 720 -TestMoney 1000000
```

要检查 1080p，正常退出后以同一档名和 `-Width 1920 -Height 1080` 启动。启动参数不会给旧档反复加钱。旧的 `ManualMedicine_20261005` 档暂时保留原样；不需要为本轮重新修改它。

## 原携带物整理

先在整备记录普通背包丹药数量及位置；方便时把仓库备用武器放进普通背包，但不要替换正在穿戴的装备。正常出发，去安全处打开背包，默认 Tab。背包不暂停敌人，危险处不要长时间整理。

预期原携带丹药与背包中未装备的武器不再只读。拖到空格、旋转未装备武器、拆分丹药、移动拆分堆到安全格，再将同来源拆分堆合并一部分，核对总数不变。非法占格和边缘放置应拒绝，失败保留原物品。已穿戴武器、护具和储物装备仍需整备更换；不能放武器进安全格，也不能局内打开仓库。

如普通初始丹药为 8，可拆出 3 放安全格，再合并 1 回原普通堆，得到普通 6、安全 2。这是示例，不要把已用药的旧档硬改成 8。出发接管只恢复真实未消耗余额；正常消耗后重启不得补回。

## 与新物及用药的关系

按 [搜索领取审查](ManualLootReview.md) 领取新物，核对原携带物让出的格子可用于新物。所有实际位置通过保存确认刷新；原携带物与新物使用同一图，但不同来源记录的同类物当前仍不能合并，会明确拒绝并保留两堆。来源容器中的放回操作仍不是主动地面丢弃。

受伤后撤到安全处，松开格挡并等待动作恢复，记录移动过的丹药位置、普通／安全数量和生命，再按一次治疗键，默认 1。预期最多恢复 35 生命且仅扣 1，HUD 与实际堆数一致。普通先于安全格；满生命、死亡、动作不兼容应拒绝，不扣药。不使用控制台降血、发物或改存档。

旧版本原局若有待确认治疗，新版先恢复该请求，再接管剩余物资；不重新发物，不退还已经确认用掉的丹药。恢复提示未消失时不要连点来试探扣药，保留日志并反馈。

## 撤离与死亡

成功撤离后，整理过的普通／安全格位置和数量应保持，原位置不能多出一份返还。保存确认后返回整备，正常转仓库或再次出发，不用调试奖励。

另一次死亡前，保留一份原携带丹药在安全格，把一份移回普通背包作为对照。预期死亡只保留当时已确认仍在安全格的内容；普通物、普通装备损失，移出安全格的不再保留，仓库、测试货币、安全格装备不变。基础补给检查整个库存：有仓库备用装备时需正常穿戴，不会再发一套可囤积补给。

## 重启与画面

整理或用药后关闭背包，Esc 暂停并保存返回入口，再正常退出。重启同档继续原局，核对移动位置、拆分堆、已经用掉的数量、搜索与领取状态都保持。接管重放不得补药；重复撤离／死亡请求也不得返还两次。不要手动编辑或删掉接管回执。

检查 720p、1080p 的背包格子、数量、预览和返回按钮，取消拖放、开关面板、窗口失焦后核对无残留移动／攻击／格挡。画面和焦点仍需要实际人工证据，无头测试不能替代。

可反馈档名、原普通数量、整理后的普通／安全数量、用药前后生命与数量、重启及终局结果，方便时附图。若有异常数量、未确认保存、恢复失败或输入卡住，保留隔离档和日志，不删除、不调试补偿；该问题路径暂不叠加开发，其余独立工作继续。本说明不代表完整 M3、M4 或最终 Demo 已验收。
