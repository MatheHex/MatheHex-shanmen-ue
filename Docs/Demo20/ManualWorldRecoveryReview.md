# Demo2.0 原局恢复人工检查（真实续局待验收）

协议已通过 Editor 编译及独立原生测试，完整文件映射与最终 Game 结果见本阶段 Report／Log；按钮和真实续局仍待人工。不要把下列预期当作实际已通过，也不要为测试手动破坏默认档、删除凭证／副本、搬移存档或运行旧 DLL。代理仍不接管游戏窗口；实时检查可晚些反馈，不暂停独立开发。

## 正常续局

使用经本阶段 Report 确认的新候选及新的独立档名，通过正常整备与出发进入青岚关。用键鼠受伤、击败一只敌人、搜索并领取少量物品；安全处用一颗丹药，记录生命、普通／安全数量、来源余量、位置和死敌。不要控制台降血、调试发物或改档。

Esc 暂停后选择保存并返回入口，再关闭和重新启动同档。应恢复原局并默认暂停；继续后生命、药品、死敌、物品和已搜来源保持最近确认状态，不重开或重抽。移动最多回退到最近世界记录；撤离读条须重新开始、按住输入不恢复。

## 故障入口

仅在后续提供可直接启动的独立故障 fixture 时检查；目前尚未交付此 fixture，不要求你制造坏档。无头用例对独立文件注入故障，只证明协议，不证明故障按钮实际显示。

对应界面预期标题为“原局恢复受阻”，主操作为“修复并恢复原局”。点击时只恢复最新精确凭证命名的候选；成功后仍须点击继续。无最新凭证／匹配副本时具体提示未修复、保留原档；不能用旧 `.bak` 恢复死敌或满血，不能用新局／补给伪造成功。重复点击不得增加代次、回血、返药或额外结算。

如果已保存的是撤离或死亡决定，而物品终局曾失败，修复后只能恢复同一终局请求；不得返回活跃战斗。出发前孤立记录修复不扣库存，仍需要正常出发确认。

- 记录档名、启动版本、修复前后提示、生命、药数、敌人／来源与终局结果；异常优先保留日志，停止该有问题路径的操作。
- 1280×720、1920×1080 检查按钮、中文换行、正文滚动和焦点；保存／修复失败不能显示已完成。
- 不使用默认 ExpeditionProfile 做故障注入，不删旧档来“解决”失败，不降级打开已使用新协议的档。
- 普通丹药已获你的正常反馈，安全格／新药／修复组合仍须单独验证；这里不改变 35 生命或一颗药的规则。
