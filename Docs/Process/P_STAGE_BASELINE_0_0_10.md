# 0.0.10 P 阶段共享基线

适用：2026-09-16 起的底层框架闭合工作；来源是用户最新范围与既有阶段验证要求。后续任务只需引用此文并写本轮增量，不复制整套交接模板。用户后续明确缩小或调整的范围优先。

## 范围

- 仅处理已批准契约中的真实结构缺口：唯一权威、Run 生命周期、身份/重放、失败关闭、Owner 转移和恢复证据。
- 不凭审计猜测新增能力。候选缺口先确认正常入口可达条件；无法证明的问题标为待核验，不伪称已复现或为其扩充包装层。
- 可以编译 Editor/Game，运行 UnrealEditor-Cmd 无头契约测试；不启动 Editor UI、PIE、Standalone、游戏程序、截图、Smoke、Cook 或 Package。
- 不接物理玩家输入，不修改正式地图/内容资产，不设计或调试玩法数值、手感、敌人、关卡、UI 表现和玩家体验。

## 执行与证据

1. 开始时核对分支/HEAD、最新已完成 Report/Log、工作区差异、既有未跟踪文件以及是否有仍运行的验证；不得重复启动或把中间结果当通过。
2. 源码修复保持最小，失败重放/保持测试使用非零状态与相同身份；不通过第二份权威、丢弃恢复状态或新 RequestId 掩盖原失败。
3. 每个生产改动路径必须由 `Scripts/ShanmenRegressionMap.json` 推导必跑组。用 `Scripts/Test-ShanmenRegressionCoverage.ps1` 验证实际日志；未知路径失败关闭。脚本和文档按其风险做专项检查，不能把“无需 UE 测试”称为产品通过。
4. 构建使用 `Scripts/Invoke-Shanmen.ps1`。区分原生退出码、外层异常/超时、源码错误和环境问题；保留首次失败与中断日志。测试结果、队列结束和进程状态联合判断，不只看退出 0。
5. 底层实现阶段核验 Editor/Game 双目标；纯文档不得伪称重跑产品测试。复用证据时明确原阶段和输入一致性；最终冻结另需完整根回归和双目标构建。
6. `git diff --check`、映射/脚本自检、原始日志 SHA-256、源码/构建基线与未跟踪文件保持证明写入 Development Log。

## 交接与结束

- 每个完成阶段只精确暂存本阶段文件，提交并推送 GitHub，提供 Report/Development Log 链接；保留无关用户文件，不强推。
- 0.0.10 不使用 CSEMI 的 BEGIN/PART/END/READY/SENT/TRANSPORT 信封、聊天附件或“下一 Prompt 已下载”完成门槛。历史 CSEMI、I 阶段文档与旧 Prompt 仅为历史材料；不得据它们恢复旧传输流程。
- 原始验证日志保留本地，GitHub Log 提供准确路径与哈希；不宣称未上传的原件已在仓库。
- Report 区分本轮事实、复用证据、待审计项和 F 阶段债务。清晰身份/结果投影属于底层接口，真实动画/音效播放和玩家体验不是由回执 ACK 证明。
- 最终底层冻结须完成 [契约与生命周期索引](../Architecture/Dev.D.UE.0.0.10_FoundationClosure_Index.md) 的有限关闭清单；全部成立后发布最终基线并暂停当前监控，不自动进入玩法。
