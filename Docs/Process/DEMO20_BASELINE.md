- 不做 Cook、Package、购买资产或发布安装包。此前暂停的自动任务不因本次手动开发自动恢复。

## 当前完整目标

当前执行 [Demo2.0 探索 Goal Prompt](../Prompt/Demo20.Expedition.goal.md)。目标已扩展为隔离新档、持久整备、二维背包及储物装备、随机搜集、撤离或死亡、安全格保留、原局恢复和再次出发的完整本地闭环。M1 至 M5 都属于本目标；首个切片或一个底层事务通过不等于目标完成。

物品与货币必须接入现有唯一权威。高额测试货币只初始化一次，不能以无限值或旧 writer 回退代替正式数量检查。真实输入、双分辨率、持久重启和性能观察仍是最终必过验收。

## 首个切片历史范围

建立“入口 → 三石卫战斗 → 撤出或死亡 → 结果 → 返回入口再开局”的独立试炼。移动、指向出剑、闪身、格挡和暂停构成本切片的可操作范围。

这是新的战斗试炼，不是已有完整探险、奖励或物品权威的替代实现。本切片没有背包、治疗、拾取、持久奖励或存档恢复；界面必须明确说明，不使用假入库或虚拟消耗冒充功能完成。

## 接线规则

场景和 Controller 只产生输入与几何候选；Session 通过现有 BasicSword、CombatCore 与 VitalityAuthority 计算并提交伤害。Widget 只展示 Session 和 GameMode 状态，按钮只发送意图，不计算伤害或持有第二份生命值。

临时试炼的身份使用既有 ID 工厂，不保存或发放物品。正式探索从唯一物品权威的 StartLoadout 回执取得 RunId，再经既有 FinalizePreparedRun 结算；普通携带损失与安全保留不能由 UI 决定。产品世界 checkpoint 只保存生命、位置、计时和终局决定，不保存物品数量，不在 Demo20 内增加库存后端。

## 验证与交付

每次交付区分已编码、自动化通过、真实窗口验证与待人工确认。改动路径必须由回归映射覆盖；保留首次失败、最终日志、原生退出码、SHA-256 和双目标构建证据。实际运行截图只能证明其展示的状态，不能替代完整游玩或性能验收。

首个战斗切片是已交付历史基线；当前阶段按完整探索 Goal 推进，不以此切片或 M1 的某个子步骤作为停止条件。自动任务保持此前暂停状态，当前目标的执行不自动恢复旧定时任务。
