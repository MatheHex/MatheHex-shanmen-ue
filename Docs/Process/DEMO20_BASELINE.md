# 山门 Demo2.0 开发基线

2026-10-04 起，按用户“抛弃之前的 Demo 材料，以目前代码框架建立新 Demo，不打包、本地运行”的请求执行。新产品入口为归尘试炼石庭，不再以旧 M01 Demo 地图、旧 UI 或旧验收截图作为新 Demo 的材料。

## 保留与重新建立

- 保留现有领域代码、确定性身份、战斗结算与生命值权威、输入注册表、构建和回归基础设施。
- 新建 `Source/demo_map/Demo20`、`Content/Demo20` 与独立启动入口。地图不复制旧场景，界面不复制旧 Widget。
- 不删除历史地图、报告、用户资产或存档。既有未提交修改不混入 Demo2.0 提交。
- 允许 UI、物理输入、场景、基础战斗与真实窗口验证；旧 P 阶段禁止玩法的历史限制不适用于本请求。
- 不做 Cook、Package、购买资产或发布安装包。此前暂停的自动任务不因本次手动开发自动恢复。

## 首个切片

建立“入口 → 三石卫战斗 → 撤出或死亡 → 结果 → 返回入口再开局”的独立试炼。移动、指向出剑、闪身、格挡和暂停构成本切片的可操作范围。

这是新的战斗试炼，不是已有完整探险、奖励或物品权威的替代实现。本切片没有背包、治疗、拾取、持久奖励或存档恢复；界面必须明确说明，不使用假入库或虚拟消耗冒充功能完成。

## 接线规则

场景和 Controller 只产生输入与几何候选；Session 通过现有 BasicSword、CombatCore 与 VitalityAuthority 计算并提交伤害。Widget 只展示 Session 和 GameMode 状态，按钮只发送意图，不计算伤害或持有第二份生命值。

临时试炼的 Run 与实体身份仍使用既有确定性 ID 工厂；新局具有新 RunId。结果不是 Profile 结算回执，不保存或发放物品。后续加入物品和奖励时，必须接回已有唯一权威链，不在 Demo20 内增加库存后端。

## 验证与交付

每次交付区分已编码、自动化通过、真实窗口验证与待人工确认。改动路径必须由回归映射覆盖；保留首次失败、最终日志、原生退出码、SHA-256 和双目标构建证据。实际运行截图只能证明其展示的状态，不能替代完整游玩或性能验收。

本切片可以交付后继续逐步扩展，但不得将首个战斗切片描述成此前 M01 全功能计划已完成。
