# 山门 Demo2.0 M2 正式探索入口 Report

## 1. 结论与范围

本轮把持久整备与原子携带接到新建青岚关：三个相连区域、固定近战／远程／精英、装备伤害和护甲、开局可用的三秒撤离、死亡损失、有限补给与再出发。增加不含物品数量的世界 checkpoint，组合原局生命、位置、敌人、动作序号、计时和终局决定恢复。

真实 Standalone 已完成提前撤离、死亡、安全格与仓库保留、穿戴替代装备、携带补给、再出发、暂停返回入口和同一受伤 Run 重启；没有控制台发物、手改存档或旧库存旁路。最终 009 候选通过 Editor／Game 构建、六组 169 项映射回归及 720p／1080p 受伤原局恢复和整备锁定页复核，本轮正式入口切片可以交付。

这是正式入口切片，不是 M2 或完整探索 Goal 完成。当前只有固定三只敌人，未达到 10–15 分钟内容量；治疗、随机计划、搜索、领取／丢弃拾回和局内背包仍未接通。完整 [Goal](../Prompt/Demo20.Expedition.goal.md) 保持活动，旧自动任务保持暂停。

新资产 `L_Demo20_JadePass` 从空地图生成，只保存正式 GameMode 和 PlayerStart。运行时建立独立占位几何、三个相连区域与宽通道，当前 57 个场景 Actor；石庭保留为显式 `-Practice` 的不结算练习。默认启动器现在打开正式青岚关，不修改旧工程默认地图。

整备确认后才进入探索。缺少武器、护具或普通行囊时继续显示具体条件；已有原局时恢复原局，不重新预留。固定近战会接近，远程保持距离并预警落点，精英扩大攻击范围和预警时间；视线检查复用世界几何。当前是固定接线切片，不声称敌人或掉落已经随机。

## 4. 唯一权威与持久启动／终局

正式出发先在只读候选中取得确定 RunId，确认该 Run 的初始世界记录，再调用既有 StartLoadoutDurable。初始世界失败不锁物品；物品启动失败留下的初始记录只允许相同未进展意图重试，不能拿有进展记录冒充新局。

终局先确认 Extracted／Defeated 世界决定，再提交既有 FinalizePreparedRunDurable。撤离返还确认剩余原物品，死亡损失普通装备与携带；安全装备、已确认安全格内容、仓库和钱包保持。请求身份从 Run 与终局原因派生；已有成功只重放，不重复返还。

终局未确认时不显示“已带回”，不允许假成功返回新局；重启继续原终局决定。暂停返回入口不结算、不释放携带，整备 EditGrid 仍由未结算 Run 锁定。没有第二份物品数量、钱包、库存后端或旧 Code A／Code B writer；物品 schema 仍为 6。

## 5. 世界记录与恢复边界

每 Run 独立记录 ContentId、同一 RunSeed、四实体生命／revision、动作序号、玩家位置与朝向、敌人位置、预警落点与计时、动作冷却和终局 Phase。RunSeed 与携带投影使用相同派生，不新增进程随机流。序号和生命 revision 继续，恢复后不能重用旧攻击身份。

记录限定不超过 1,024 字节，有固定内容戳、长度和完整性摘要；精确旧字节 CAS → 临时写入／flush／校验 → 旧文件备份校验 → 替换 → 读回确认。替换后读回不确定时保持同一候选，精确重试接纳已写字节，不再增加一代。该摘要不是安全签名，也不是 Report 使用的 SHA-256。

战斗变化在保存确认后发布；移动与计时约每秒确认，正常退出另保存。原局重开默认暂停，撤离读条重新开始，按住的输入不恢复。主文件缺失、损坏或内容不匹配失败关闭，不静默回退旧备份复活敌人；当前无玩家修复入口。搜索、来源及新搜集物尚未产生，不能把当前恢复称为完整 Goal 恢复。

## 6. 界面、计算与内存

复用当前 Widget、Controller 和整备投影，新增正式入口、继续原局、区域 HUD、处理中／确认终局、保存重试与原局保留。Esc 在正式探索中实际暂停世界；表面切换清空输入、格挡和移动。无行囊时显示“未装备行囊”，原局锁定时改为“原局携带已锁定”，空装备格不宣称原局装备丢失。该状态由 InspectActive 在快照刷新时只读缓存，不在 Paint 扫描回执。有限补给明确只补缺失项目，仓库替代装备和丹药需自行穿戴／携带。

世界文件当前 333 字节，仅表示序列化体积，不代表运行内存。每秒同步确认写盘、战斗候选复制、物品快照复制与历史回执扫描均有成本；旧 Run 文件也尚未整理保留策略。没有实测帧耗时、峰值内存或多轮 Actor／UObject 释放，不能据文件小宣称性能合格；这些仍属于 M5。

## 8. 首次失败与修复

首次 Editor 构建原生 6、21.266 秒、外层 1，Game 未运行：UE 5.8 GetPawn 返回 TObjectPtr，五处 `auto*` 推导失败，改为显式 APawn 指针。首次回归 26 Success／2 Fail、Queue 28，UE 原生 0、外层正确拒绝 1；新增护甲层缺必要标签导致 Resolver 拒绝，补齐 DefenseArmor 标签，保留非零生命算术断言，不改期望掩盖生产缺陷。

实际死亡后发现“补给”原文暗示装备已自动穿戴，改为明确自行使用仓库替代装备；目录与背包页撤掉不适用于正式探索的“尚未出发／续局尚在接通／试炼不结算”旧提示。首次恢复立即暂停出现近地背景，005／006／007 修正均未解决；诊断证明摄像机缓存正确，本机 UE GetPlayerViewPoint 却要求缓存时间大于零。原局在世界时间零暂停，因此默认退回角色位置。008 在正式模式已初始化缓存且首次暂停时使用正确缓存，009 两种分辨率均实际验证俯视恢复；没有推进一帧战斗来绕过问题。失败原件不覆盖。
