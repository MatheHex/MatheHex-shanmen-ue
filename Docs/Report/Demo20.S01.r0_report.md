# 山门 Demo2.0 首个战斗切片 Report

## 1. 目标与范围

本阶段按 2026-10-04 的新请求启动 Demo2.0，以现有代码框架重新建立本地运行的 Demo，不沿用旧 Demo 地图、界面或演示材料，不打包。

交付对象是“归尘试炼”的首个战斗切片，不是此前 M01 全功能计划的完成声明。旧文件、历史报告和用户未提交修改保留；自动任务未恢复。

## 2. 新产品入口

- 新地图：`Content/Demo20/Maps/L_Demo20_StoneCourt.umap`。
- 新本地启动器：`Scripts/Start-Demo20.cmd` / `Scripts/Start-Demo20.ps1`。
- 新角色、Controller、GameMode 与 UMG 页面，均在 `Source/demo_map/Demo20`。
- 场景由引擎基础几何体构成，不依赖旧 Demo Blueprint 或旧地图；采用占位美术。
- 旧 `Config/DefaultEngine.ini` 的默认地图不改写；新启动器显式指定新地图。

## 3. 玩家流程

入口说明 → 进入石庭 → 移动和鼠标指向出剑 → 闪身或格挡石卫蓄势攻击 → 击败三座石卫 → 返回青色归阵撤出 → 结果页面 → 返回入口再开局。

另有死亡、暂停、主动结束和窗口失焦暂停路径。每局初始化 100 玩家生命、3 座 78 生命石卫；剑击 26，石卫攻击 18，格挡减免 75%。这些是本切片可修改的初始调试值，不代表正式平衡设计。

## 4. 复用框架与权威边界

输入注册表 → 新 Controller / 几何距离与朝向判断 → Demo20 临时 Session → BasicSwordExecution / ActionOrchestrator → CombatCore 防御结算 → VitalityAuthority 提交 → UI 只读展示。

UI 不计算伤害、不直接写生命、不扣库存。Run 和实体身份通过现有 ID 工厂派生。每局生命值权威和命中账本在返回入口后释放，下次使用新 RunId。临时试炼不是 Profile 结算服务，也不声明完成来源接纳、库存消费或奖励落盘。

## 7. 实际运行与未验收范围

已使用本机 UE 5.8 `UnrealEditor.exe -game` 打开新地图的真实游戏窗口。首次发现按钮文字换行与开始后焦点误暂停；修正后重新构建，最终窗口可正常进入试炼。另修正默认材质不响应颜色参数的问题，交付独立调色材质，归阵青色、石卫棕色及预警橙红色在窗口中可见。

真实观察通过：中文入口、HUD、鼠标指向和空击提示、Space 闪身位移、过早归阵拒绝提示、石卫蓄势范围、敌方伤害直至死亡结果、返回入口再次开局（生命恢复 100、目标恢复 0/3）、Esc 暂停页面。截图见 [入口](../Demo20/Evidence/entry.png)、[场景](../Demo20/Evidence/arena.png)、[预警](../Demo20/Evidence/telegraph.png)、[死亡](../Demo20/Evidence/defeat.png)、[再次开始](../Demo20/Evidence/restarted.png)、[暂停](../Demo20/Evidence/pause.png)。

当前输入工具无法可靠维持长按，观察间隔也不适合实时战斗；没有以注入领域命令替代实际操作来伪造通关。成功命中和撤出已有领域自动化，但真实键鼠完整击杀/撤出、持续 WASD、持续格挡仍待人工验证。启动请求 1280×720，Windows DPI 缩放后窗口截图为 1922×1128，不能将它算作另一次 1920×1080 验收。

尚不能以 Session 自动化替代真实键鼠完整通关、持续按住格挡、PIE、双分辨率、帧耗时、运行内存或多轮对象释放验收。
