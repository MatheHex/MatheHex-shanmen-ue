## 3. 复用与真实结构缺口

旧容器拥有槽数组、物品拥有唯一父容器与锚点，但没有多格尺寸、方向或二维碰撞契约。直接在 UI 中另记位置会造成第二份放置真值。

本轮在 ShanmenItems 快照中追加 Grid 几何与策略：数量、Owner、作用域、物品身份仍只来自既有 ItemInstance；方向属于 Grid，锚点仍是既有 SlotIndex。生成来源、数量预留、事务回执及持久服务继续复用，没有另建库存后端。

## 4. 已编码能力

| 能力 | 当前实现 |
| --- | --- |
| 几何与预览 | 定义宽高、方向、容器二维布局、边界及占格冲突检查；预览不变更快照 |
| 移动与旋转 | 同一命令提交锚点、父容器、方向；失败无变更 |
| 拆分 | 创建确定性新身份，减少原堆叠；精确重试不再创建物品 |
| 合并 | 同定义、同归属、相同奖励元数据；只合并目标可容纳数量，余量留原来源 |
| 全量合并 | 原身份保留 Depleted 审计墓碑，不保留第二份活物品 |
| 放置策略 | 安全格允许标志、装备角色匹配、单个逻辑装备槽、禁止储物嵌套的策略 |
| 并发与失败关闭 | 校验内容、Owner/作用域、权威及物品 revision；待决预留和旧单槽容器不能绕过 |
| 持久入口 | Repository → AuthorityService → GameInstance Subsystem，保存确认后才返回成功 |

安全格目前仅实现放置策略，不证明死亡保留已经接通。装备槽放置不证明装备属性已影响 Demo 战斗。两种背包容量切换及缩容保护仍需产品接线与原子命令。

## 5. 身份、回执与唯一权威

请求指纹包含完整意图、作用域、内容和预期 revision；接受后精确重放返回原回执，同 RequestId 的不同意图拒绝。Split 身份由确定性命名空间和请求/来源身份派生。

拒绝不记为已执行命令、不修改库存。保存失败通过既有事务服务回滚完整候选；同一失败请求可安全重试。成功命令进入既有 ProcessedRequests，重新打开后继续幂等。

新网格入口不允许待决 Reserved 资源被搬动，也不静默退回 Code A/Code B 或旧单槽 writer。当前只处理合法 Stored 物品；局内携带/新拾取治疗与 Run 协调还需正式接线，不能据此宣称完成所有局内操作。

## 6. 存档兼容与计算边界

持久权威 schema 4 → 5 的必要变化是 Grid 字段。schema 1–4 先验证原格式摘要，再以内存空 Grid 规范化；当前 schema 显式要求 Grid。旧产品 Profile schema 未在本轮改动。

新增 N−1 测试使用 12+18 的非零材料库存：独立计算 schema-4 wire 摘要、篡改数量拒绝、只读迁移不写盘、授权规范化只增加一代、库存及旧初始摘要保留、再次打开不写盘。已有 schema 1–3 夹具只移除新增字段以保留历史格式，没有放宽原校验。

几何验证使用临时位集并限制布局/定义/总格数，避免逐物品两两扫描；这些是派生计算，不是第二份库存。完整候选快照与历史回执验证仍有拷贝/历史增长成本，须在 M5 实测。不将序列化大小或位集理论大小冒充实际运行内存。
