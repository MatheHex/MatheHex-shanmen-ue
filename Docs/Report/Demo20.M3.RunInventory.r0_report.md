## 3. 单向接管与唯一权威

新增 `MaterializeRunInventory` 请求，只接受 Owner、Scope、Run、内容和确定性请求身份，不接受调用方数量。Repository 从原出发预留、已确认旧消费和旧治疗终结回执重建精确剩余量。相同原 Item ID 恢复为 Stored，放回其原携带格；没有新增物品定义、实例、货币或第二份库存。

出发前已有安全格物仍在同一图，不参与普通携带预留。已穿戴装备保持原 DeploymentLock 与整备更换规则；普通背包内未穿戴武器护具解除当前部署标记，进入实际 Stored 图。已用尽数量保持零 tombstone，不补回；储物装备不允许嵌套。

请求 ID 按 Owner／Scope／Run 派生，回执记录接管的原预留 ID 与历史总量。同一请求重放原回执，移动、拆分、使用、死亡或重启后不会重新补回余额。载入核对请求／fingerprint／receipt ID、原出发绑定、时序、精确预留清单与历史数量，旧全额预留数量没有接管回执时不得变成实际可用数量。

## 4. 持久化与旧记录恢复

AuthorityService 复用原锁、候选快照、原子替换和重读证明；Subsystem 仅增加既有 Ready／GameThread／Owner 检查的薄端口。没有绕过拒绝或退回 Code A／Code B。替换前失败保持精确原态；替换后若既有服务重开证明精确后态，可确认一次接管，否则不报成功。

存在未终结旧数量或资源意图时不接管。GameMode 在新出发、原局打开和原检查点重试接线；旧世界治疗意图先走原恢复，再接管真实余额。终局旧世界不强制接管，保持已有结算语义。失败暂停并明确提示未确认，不换请求身份或假发物。

接管后原 `ConsumePreparedRunItem`、数量意图 Prepare／Finalize 拒绝该局新的旧账本消费；已经确认的精确旧请求仍可重放，不再修改数量。实际 Stored 丹药继续使用既有 Reserve／Commit 与世界治疗意图，不改生命恢复、动作互斥或冷却。

## 5. 格子操作和中文界面

接管后 Run 投影就是实际物品图，不再叠加虚拟普通数量。既有 `EditActiveRunGrid` 可移动、旋转、拆分和同来源合并原物及新物，合法数量物可移入／移出安全格；预览仍从真实快照验证，提交只发正式命令。局外仓库不在局内开放，整备写口仍锁定。

InventoryWidget 去除过时的原携带只读提示，保留武器／护具不能进安全格、已穿戴与储物装备仅整备更换等明确理由。当前元数据不同的同类堆仍不能合并，两堆保持；本轮没有偷偷删除来源记录来实现跨来源堆叠。

HUD 和原物整理后的治疗读取同一 Stored 图，普通先于安全格。普通药移动到安全格后按实际安全归属使用与保留；移出后失去死亡保护。没有新增 UI 后端、Tick 数量缓存或地图修改。实际拖放、预览、输入焦点及双分辨率仍需人工证明。

## 6. 撤离与死亡

接管回执指明哪些原预留已转入实际图。Loadout 的旧返还摘要不再列这些物资，FinalizePreparedRun 对其只关闭原预留，不恢复原数量或原格子；调用方企图再提交返还数量会拒绝。既有局内终局在同一次持久提交中处理实际图。

撤离保留已确认普通／安全格物的位置、数量和旋转，不重复返还；死亡／放弃损失普通背包 Stored 内容，实际仍在安全格者保留，从安全格移回普通背包者损失。未领取的本 Run 来源物仍销毁，不算奖励。普通装备、仓库、测试钱包和安全格装备沿用已确认规则。

精确终局重放与原生重开不重复保留或清理；返回整备及下一局走已有正常出发、补给和装备端口。历史未接管局保留旧终局路径，不能拿本轮图语义重新解释所有旧回执。

## 7. 兼容与内存边界

物品 Schema 6 不新增字段，operation enum 仅尾部追加，旧数值与原整备 fingerprint 不变。世界格式、大小、内容 ID、随机种子和旧来源计划不变；原物治疗使用前一轮已经新增的 StoredCarry Origin 2，不再新增世界字段。新版读取旧记录，旧 DLL 不支持新增操作，切换版本需先正常退出旧进程。

接管仅增加一条确认回执，并保持原实例数量不增加。实际 UI 刷新仍有快照复制，IsTransferred 在确认与恢复时读取历史回执；没有新增每 Tick 的接管或第二份数量缓存。这只是代码观察，不是低内存或无泄漏证明。真实帧耗时、运行内存、历史回执／tombstone 增长及多局对象释放仍待实测，不拿序列化文件大小充当内存。
