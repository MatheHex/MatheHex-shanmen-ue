# 山门 Demo2.0 地面丢弃与拾回 Report

## 1. 结论与范围

本轮接通主动地面丢弃与再次领取，不把放回宝匣当作丢弃。普通背包与安全格的合法 Stored 物品可整堆移到地面行囊，保持原 Item ID、数量、来源和方向；拾回复用现有局内格子事务。地面内容不随撤离带回，也不享受死亡保留。

已编码，固定最终输入的 Editor／Game 双构建与八组改动驱动原生回归通过：264 Success／0 Fail、264 个去重路径，原生码与外层均 0；十九路径覆盖门通过。完整证据、首次原件与 SHA 见 [Development Log](../Log/Demo20.M3.GroundDrop.r0_log.md)。本轮没有实际窗口或截图，人工步骤见 [地面丢弃审查](../Demo20/ManualGroundDropReview.md)。普通丹药旧基线人工主路径反馈保留，不改药量、冷却、伤害或敌人难度；完整 Goal 未完成。

## 3. 唯一权威与稳定身份

新增 DropActiveRunItem，整堆转移不接收 caller 数量。必须是当前 Owner／Scope／Run、已接管的普通背包或安全格 Stored 物品；不允许仓库、已穿戴、储物装备、外局来源或未关闭的数量预留。物品与权威 revision 错误均拒绝，失败不改变原图。

请求 ID 由 Owner／Scope／Run／Item／物品 revision 派生。相同请求和 payload 重放原回执；改变位置或 revision 不能冒充原请求。地面容器按请求派生，不接受 UI 任意世界容器 ID。丢弃后再次拾回，再主动丢弃属于新的已确认 revision 与新位置，不是原请求重复。

## 4. 持久位置与兼容

地面位置采用整数厘米，编码到现有 PurposeId 的版本化规范串，回执记录原 Item ID、当前 Run 和派生容器 ID。载入重算请求／fingerprint／receipt ID，校验 Run 开始、接管及终局时序、Owner／Scope、容器类型／尺寸和互相绑定；孤立地面容器或被篡改位置拒绝载入。

Item Schema 6 不新增字段，operation 只尾部追加；世界检查点格式、源计划、目录、RunSeed、随机内容版本和原治疗 Origin 均不变。新版可读取无地面记录的旧档；旧 DLL 不认识新 operation，切版本须先退出旧进程。位置属于已确认物品回执，世界移动检查点最多一秒的回退不会重生成地面物资。

## 5. 产品接线与 UI

AuthorityService 复用原锁与原子持久命令，GameInstance Subsystem 只增加 Ready／GameThread／绑定 Owner 的薄端口。GameMode 在背包打开、当前 Run 和无待确认治疗／检查点时，检查脚下真实碰撞地面，再提交正式命令。UI 只显示确认结果，不写数量或自行生成掉落。

局内工具栏第四项改为“丢弃所选整堆”。部分丢弃可先拆分再选择，整备工具栏保持装备替换。地面行囊复用独立占位材质与基础形状，无碰撞；金色有物、灰色拾空。交互使用既有注册表绑定，180 厘米内且视线可达，直接打开实际来源格，不重新随机搜索。已拾空行囊不阻塞附近宝匣交互。

地面 Actor 仅持有容器映射，不存数量。投影在恢复、丢弃、格子事务和终局时更新，不新增每 Tick 的权威快照读取。当前 Run 结束后销毁地面表现并从 ArenaActors 引用中移除。显示失败明确提示已保存而未显示，同步暂停世界并刷新界面，不能把重新丢弃当作修复；地面读取失败也停止后续来源交互。

## 6. 拾回、容量与终局

拾回复用 EditActiveRunGridDurable，当前 Run 仅可触达已确认的本局地面容器。非法占格、空间不足或保存失败时，物品留在地面；同来源合并可部分成功，剩余数量保持原地面 Item 身份与来源。重复打开、重启及旧丢弃请求重放不会补满容器。

FinalizePreparedRun 同次持久提交销毁尚在本局地面容器的 Stored 物品，适用于撤离、死亡和放弃；拾回普通／安全格则按实际最终位置结算。安全格主动丢出的物品即失去保护，不恢复到原安全格。仓库、钱包、护命匣和其他实际安全内容不受影响。下一局不能读取或移动上一局地面内容，历史精确请求可重放但无新副作用。
