## 3. 唯一权威与统计口径

RunReport 是只读结算事实，不是第二份物品数量权威。出发记录绑定 Owner／Scope／Run／开始 revision；领取操作只在现有局内网格候选成功后累计，终局从清零前的实际投影与清零后的同一候选冻结结果。命令不读报告来发奖、消费、预留或返还。

“搜寻取得”明确是搜寻容器到普通背包／安全格的累计取出量。部分合并只计实际转入，生成、只看、未拿和地面取回不增加；退回搜寻容器再取出会再计一次操作。它不是每单位去重的收益，也不是额外奖励；界面说明此限制。混合堆不按接收堆出生元数据猜测每颗药的原始来源，不增加 FIFO／批次来源账本。

## 4. 终局数量与不重复执行

消费只计本局开始之后、终局之前的成功直接消费、已提交数量意图或实际数量 Commit；出发扣入携带、Reserve、Cancel、失败和精确重放不算消费。加载时独立核对消费回执，防止仅修改展示数字。

撤离带回包含出发携带、已穿戴装备和安全格，不把它全称作新奖励。死亡损失在物品被销毁前保存非零数量，安全格与护命匣按终局实际归属保留。场景遗留仅统计本局已落实来源／派生地面容器，单列未领取物和未取回丢弃；未搜索、未落实的潜在内容不猜测。局外仓库不计入本局奖励或损失。其他 Owner／Scope 的并行消费不计入本报告。后续有限补给和整理不能改写既有闭合历史；重复点击、重复终局和恢复只复用已有回执。

兼容旧未接管网格的合法“只返还部分携带”契约，不让新增审计阻断旧操作：声明未返还余量独立记为 Lost，并以“未带回携带”显示，不冒称丹药消费或死亡。新版实际图终局不使用 caller 数量，正常撤离带回图中全量，Lost 应为零；旧 slot 无网格局不新增报告。

为在死亡实例清零后保留历史数量，同一物品文档新增 RunReports 审计字段，Item Schema 6 → 7；这不是库存后端重建。旧 Schema 1–6 先按各自历史规范串验证 digest，再补空报告；不把新字段混入旧哈希。6 的原生 genesis、初始证据和非零活动局仍可读取，不重发初始物资。

旧局没有完整领取统计起点，明确显示历史不可用，不补造零统计；原终局仍可完成，下一新局才开始完整记录。只读加载不改磁盘字节；下一次合法写入升级到 7。旧 DLL 不认识新文档，不能降级打开已经升级的档。世界编码、来源内容和药品意图布局不变，不读取或覆盖旧真实玩家存档。

## 6. 玩家界面与重启访问

终局保存确认后，已有结算卡显示中文物品名与数量；保存未确认不展示成功数量。正文为限高滚动区域，返回／重试按钮在其外，不让长列表把操作推到屏外。技术身份和详细诊断仍只进日志。

整备页提供最近已保存的物品结算只读入口，用于重启后检查历史；不重新执行终局，也不依赖已结束 World 的 Actor 或当前仓库数量。只显示已闭合、归属匹配的记录，不拿活动局冒充已保存结算。其实际显示、按钮和焦点尚待人工，不以格式化字符串测试替代渲染。

## 8. 内存与增长边界

报告每局按实际定义聚合，不保存逐帧库存副本；产品只在加载或终局确认时生成展示缓存，不每 Tick 抓完整物品图。事实仍参与已有候选复制、序列化和校验，会增加分配与计算成本，不声称零成本。

报告最多 4096 局、单报告最多 65536 行，沿用持久文档大小限制；达到限制失败关闭，不无声删历史或重置库存。历史容器、回执与报告持续增长，长期压缩／归档、真实内存和多局对象释放尚未实测；磁盘字节数不当作运行内存。
