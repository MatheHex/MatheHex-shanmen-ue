## 5. 容量与信息交互

仍保留 64 MiB 原始文件门、深度/重复键检查和来源数量上限。本轮解码会暂存每个物品的元数据，随后移动进物品数组；该暂存随物品与词缀数量线性增长，且 JSON DOM、默认占位元数据、前后快照、序列化文本和文件缓冲仍可能同时驻留。

没有 RAM 峰值、长时吞吐或锁持有时延验收，不以文件大小上限代替内存预算。整份快照校验、旧格式摘要计算与锁内全量保存的规模债务仍在。后续 UI 应读取权威的只读摘要，不能把磁盘 JSON 或整个历史副本当第二份可写库存。
