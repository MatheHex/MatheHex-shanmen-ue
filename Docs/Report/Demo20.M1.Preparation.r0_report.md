## 3. 唯一权威与原生隔离档

新增明确的 NativeProfile 入口，而不是伪造旧 Code A／Code B 导入证据。沿用同一 AuthorityService、Repository、GameInstance Subsystem 与原子文件发布协议；原生来源的历史字段为零，来源身份和初始摘要在文档校验中验证。旧迁移入口不能接纳原生标记。

已有同来源／内容档只读取已确认状态，不再创建初始物品。重新打开时核对冻结的定义、尺寸和储物规格；坏档、其他产品来源和不一致目录失败关闭。一次发布读回不确定时重开同一来源核对，不补发第二份库存。

新档默认装备基础剑、道袍、6×4 行囊和 2×2 护命匣；普通背包有 8 颗丹药，安全格有 1 块碎玉佩，仓库有替换装备和材料。测试钱包默认一次性 1,000,000，可配置初始值；已有档即使启动参数改为 999,999,999，仍保持原来的 1,000,000。无商店系统。

| 操作 | 当前产品能力 |

## 5. 储物容量与原子失败

普通背包容量由同 Owner／作用域下唯一已装备储物定义决定：基础 6×4，扩容 8×5；安全格为 2×2。不能独立改 UI 或容器宽度获得容量。未装备时容器禁用且必须为空；旧无储物定义的快照继续使用既有静态布局。

更换宽度保留内容的 X/Y，并重新计算锚点及受影响 revision。不自动整理、不溢出、不删除内容。旧装备放不回、较小行囊放不下、非空容器被卸下时，整个候选拒绝，包括装备、容量、数量、位置和回执。保存失败同样完整回滚，安全重试沿用原请求。

储物装备只能放仓库或对应装备槽，不允许普通背包／安全格嵌套。安全格本轮仅验证放置规则；死亡保留和终局清算仍属 M4。
