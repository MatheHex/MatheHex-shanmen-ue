## 4. 确定性与目录

把旧奖励生成器内部 xorshift64* 流原样提取为共享值类型，保留零种子兜底和有界整数规则，不引入全局 RNG。新产品复用旧稳定种子哈希，先用确定性身份按 Run、RunSeed、来源内容、规范角色和 Position／Loot 通道隔离，再分别取样。搜索顺序和 cursor 不进入随机种子。

六个固定角色为三宝匣和近战／远程／精英遗物。每区宝匣在 `X=800+2100×区序、Y=±620、Z=40` 两个固定候选中选一，远离出生、归阵、门口和柱子。普通守卫一至两条、宝匣两至三条、精英三至四条，来自九项固定目录的有限数量。没有随机词条、货币掉落、商店或储物装备嵌套；生成分值仅记录计划算术，不是钱包余额。当前敌人仍固定三只，随机组合待接。

## 6. 持久化与失败语义

物品 Schema 6、原世界 333 字节及治疗可选 366 字节记录不变。来源接纳作为搜索完成的持久确认，未完成的临时计时不恢复，需重新开始。保存全部已解析计划、来源／容器／物品身份，但不插入已领取物品或容器图。原携带药数、安全格、仓库、Grid 和 Reservation 不因搜索改变。

替换前失败回滚精确原档，不能发布预览。替换后首次验证失败，原 Service 重新打开并证明精确后态时允许 ResolvedAfterReopen，不能把已证明结果错误当未知。若重读不能证明，例如两个生命周期写入分歧，则关闭读取和预览，保留新档，要求恢复；不换来源、不重抽、不退回旧库存。
