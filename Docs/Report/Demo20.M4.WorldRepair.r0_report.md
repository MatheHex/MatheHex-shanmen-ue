## 2. 问题与范围

原世界记录校验失败会关闭续局入口。已有 `.bak` 是上一代，直接采用会使已击败敌人复活、生命回退，或与已提交的物品消费不一致。因此本轮不增加自动回退，而是在同一产品世界持久协议中保存最新代精确凭证和同代副本，给失败入口提供显式安全重试。

只修改 Demo20 世界记录、现有 GameMode／Widget 接线及对应测试；不修改物品数量权威、物品 Schema、随机内容版本、治疗数值、地图、输入、资产或旧 Code A／B。修复不启动新局、不发物、不退药、不结算。旧暂停的自动任务不恢复，代理不操作窗口。

## 3. 同一记录的持久协议

原 `.world` payload 布局保持：无用药意图为 333 字节，有意图为 366 字节。新增 `.head` 为 76 字节的高水位凭证，绑定 Run、代次、精确候选摘要及前驱摘要；不是第二份活跃世界或库存。`.replica` 保存相同编码字节，不独立决定世界状态。

正常保存先校验原 CAS，写入并读回候选临时文件，再持久接纳高水位，原子替换主记录、核验并更新同代副本。接纳后替换前中断，意味着“候选已持久接纳、替换待完成”，不是已经向玩家确认成功。加载不能越过高水位选择旧主记录；只允许显式补完该精确候选或原请求精确重试。相同代次的新意图不能替换已接纳意图。

## 4. 修复规则与保留原件

修复只在主记录、同代副本或准备好的临时文件中寻找与最新凭证完全匹配的字节，校验内容／Run／代次。绝不使用 `.bak` 建立最新代证据，也不按内容模板重建生命、位置、敌人、预警、种子或用药结果。

覆盖损坏主记录前，将原字节保存为独立诊断原件；已有同名原件必须完全相等。不可读或超过 1024 字节的原件拒绝覆盖，不无声截断或删除。可读的零字节原件允许精确保留后修复，但零字节主记录仍不是可加载 checkpoint。替换前后重读凭证与主记录，失败不发布输出对象；重复修复不增加代次。凭证缺失、损坏、跨局或无最新匹配副本时保留原档并提示人工检查。

该协议沿用本地单 writer 的运行假设，不宣称跨进程文件锁、抗人为伪造或任意磁盘故障恢复。主记录、凭证和副本同时丢失时不能推定恢复成功。

## 5. 玩家接线

当前物品活动局身份或正常出发预检身份决定修复目标，按钮不接收任意 Run。恢复入口失败时暂停世界、禁止普通出发与库存操作；修复成功后重新走既有物品身份、待确认用药、实际背包接管、来源／地面投影及终局链。活跃原局默认保持暂停，待玩家继续，不恢复按住的输入。

出发前孤立世界记录只允许与同一正常携带预检匹配；修复本身不扣携带，完成后仍须点击正常出发。修复拒绝时保留按钮供安全重试，不伪报已保存或已带回。技术 ID 与代次留开发日志，玩家界面显示具体中文原因。

## 6. 兼容与边界

健康旧 `.world` 且没有新 sidecar 时只读加载不改盘；下一合法保存才接入凭证和同代副本。损坏旧档没有最新凭证，不从历史 `.bak` 猜造恢复。新副本存在而凭证丢失亦失败关闭，不冒充普通旧档。

payload 不变不等于支持降级：旧 DLL 不识别高水位，不应写入已使用新协议的档。原 Item Schema 7、来源生成历史、数量真值、结算审计、合法重复终局与新旧内容 r1／r2 保持原契约。
