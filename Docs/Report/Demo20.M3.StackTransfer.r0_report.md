## 3. 普通与特殊物品兼容

同 Definition、Owner、Scope 的可消耗数量物，出生元数据仅普通来源角色不同或一方为普通整备来源时允许合并。两边元数据必须有效；判断只使用临时副本检查普通属性，不能擦掉实例和计划上的来源。

特殊奖励、稀有价值、倍率、词条或事件身份不同，仍不合并。原先元数据完全一致的合法特殊堆行为保留。纯政策测试覆盖普通来源、空整备元数据、不同 Jackpot 事件、稀有奖励、词条和相同但无效的元数据；本阶段未新增特殊奖励或随机词条玩法。

## 4. 来源记录的语义与限制

实例 RewardMetadata 表示该身份的出生记录，不表示堆中每个当前单位都来自同一出生事件。合并不改它；来源被并空后仍保留 Depleted 身份和元数据。接收堆继续使用原 ID，数量在同一候选里增减；部分合并留下原位置、原身份及余量。拆分子身份继续按原确定性派生规则创建，继承父身份出生记录。

新 `Grid.Merge.r2`／`Grid.Split.r2` 回执用现有 ReservationIds 记录 `[来源实例、接收／子实例、完整性 witness]`。第三项是校验见证，不是物品或资源预留。回执保留实际转移量、来源前后数量、revision 与原命令 fingerprint；载入核对记录形状、双方存在和作用域、定义、拆分子身份、出生一致性或合并兼容性，以及见证。

这是已确认的历史转移边，不是第二个库存，也不是逐单位批次／FIFO 账本。不能仅从接收堆的出生字段推定某颗药的原始来源。见证用于发现回执字段的错误或不一致，不是密钥授权，也不替代物品文档原有 digest、来源接纳或完整事务历史校验。旧回执没有参与双方，不猜测补写；历史来源粒度保留为原有范围。

## 6. 治疗与终局组合

混合后的数量走现有实际物品图。治疗用同一正式预留／提交端口，先扣药再保存生命确认；生命保存失败保持待确认原意图，恢复不再扣第二颗。没有改治疗量、动作、冷却或敌人难度。

安全保护依据终局时的已确认位置，不依据出生角色。混合堆拆入安全格后死亡保留，普通位置损失；丢出安全格失去保护，拾回按最终位置。撤离不会从旧整备账本重复返还已合并的原药，世界中未领取余量不算带回。原生测试组合实际混合、拆分、地面往返、死亡／撤离、重启和重复终局。
