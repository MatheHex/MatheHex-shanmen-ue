## 下半部分：授权执行内容

### 4. 单一授权目标

自动恢复可用的 Windows UI 控制链，并以同一活动工程中的真实 UE 游戏窗口证明：

    可枚举并唯一绑定目标窗口
      → 可取得当前状态／截图
      → 可将真实 OS 输入送至前台 UE 窗口
      → 可观察到一次无副作用 UMG 导航的真实界面变化

达到该目标后立即停止，不执行 F0 的 BasicCache、P49、P50、P31、拖拽、拾回、保存或任何游戏产品验收。

### 5. 自动诊断与恢复顺序

1. 记录开始时间、活动工程、Editor PID／窗口标题、当前 `git status --short`；只读记录，不清理或重置工作树。
2. 尝试当前首选 Windows 控制路径：枚举窗口、唯一选择活动 UE Editor、取得窗口状态或截图、确认前台焦点。若此路径完整成功，继续第 6 节。
3. 只有第 2 步出现异常时，按第 3 节第 5 条记录最早异常并分类：
   - 控制会话／执行上下文失效；
   - 过期窗口绑定或窗口已退出；
   - 目标窗口未成为前台或未响应；
   - 控制服务本身不可用；
   - 其他有证据的环境原因。
4. 对会话／绑定类问题，自动执行最小恢复：清除仅本次控制会话的临时绑定，重新初始化控制会话，重新枚举窗口，按标题、PID 和进程存活状态唯一绑定真实 Editor；不得猜测或复用旧句柄。
5. 重新取得状态／截图。若仍失败，自动使用一条已获允许的替代本地桌面输入路径（真实 OS 前台窗口操作，而非 UE 内部调用），重新完成窗口枚举、前台焦点、截图／状态与输入验证。
6. 两条路径均须有明确上限：首选路径的首次尝试＋一次恢复重试，以及一条替代路径的一次完整尝试。三次均不能获得可审计的窗口状态时停止；不得无限重试、重启 UE 工程、修改 UE 代码或把不可验证的操作标成成功。

### 6. 真实输入前置验证

仅在第 5 节已成功取得当前窗口状态与前台焦点后执行：

1. 从活动 Editor 正常启动一个可见的 PIE／New Editor Window 游戏窗口。记录 Editor 与游戏窗口标题、PID（如可得）、窗口截图／状态、启动时间；不得启动未 Cook 的独立二进制、Cook 或 Package。
2. 唯一绑定可见游戏窗口，取得一次输入前截图／状态。
3. 在视觉可见、具有正常点击目标的宗门／游戏 UI 中，选择一个不会创建、移动、装备、丢弃、搜索、开局、保存或改变物品真值的导航控件（例如已有页面的只读标签、返回、说明或同级页面切换）。先用真实前台鼠标点击，再用真实键盘完成一个无副作用的焦点／返回动作；不得使用盲点坐标或直接 Widget 调用。
4. 取得输入后截图／状态，证明界面焦点或可见导航状态确实发生了预期变化，且不产生 Run、P5/P6/P8、P9、WorldDrop、profile 或 Save 写入。
5. 若可安全从 Editor 发起可见 Standalone Game 窗口，重复第 2—4 步一次；若该窗口不能在不扩大范围的前提下启动，记录该项为未执行，但 PIE 的真实游戏输入前置仍必须完成。
6. 关闭本任务打开的运行窗口；不得以运行窗口的关闭／重启作为产品状态或修复成功证据。
