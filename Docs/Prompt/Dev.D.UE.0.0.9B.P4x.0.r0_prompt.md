## 2. 本次策划修订

此前的“备战”被用作进入游戏、初始化人物装备或初始化物品状态的前置阶段，已经两次造成：

1. 玩家无法开启游戏；

自本任务起，备战阶段从正式开局链中删除。局外仓库/人物整理仍可作为独立的物品管理页面存在，但不再是开始一局游戏的阶段、门槛、初始化器或有效性判定来源。

具体地说：

- 点击开始游戏必须直接走既有的地图/Run 启动链；
- 开局不得创建、恢复、重置、校验或依赖旧备战布局、旧备战装备、旧空间道具引用或旧备战 UI；

- 不要求玩家在进入地图前装备任何物品；
- Code B P3/P4 Host 仍默认关闭，开始游戏不得为了物品系统而创建 Code B fixture、Repository、页面或拖拽对象；
- 旧备战页面/类型若其他历史代码仍引用，可以保留为不可达的遗留代码；本任务删除的是行为和启动依赖，不授权盲目删除仍被使用的源文件。

这是一项明确授权的、最小范围的正式启动路径修正。它不是把 Code B 提前接管 Profile、Run、SaveGame、Loot、地图、玩家 Actor 或默认 UI。

## 4. P4x 的物品操作契约

### 4.1 普通储物位置

局外仓库、基础 6 格、快捷空间内部格和非快捷空间储物囊内部格都是普通储物位置。它们不以物品类别互斥，也不因为物品是否为装备而拒绝正常存放。

在这些普通位置之间：

- 物品移动、交换、兼容堆叠合并和替换全部由真实拖拽 Drop 完成；
- 兼容堆叠物可合并；装备本体仍不可堆叠；
- 容量、目标占用可否交换、同源、Revision、唯一实例、循环嵌套和父子容器原子性仍是必要安全规则，不属于装备栏位的类别互斥；
- 空间容器本体为空时可像普通物品一样拖拽；其内部已有内容时，沿用已接受的 LoadedSpatialItemMoveUnsupported 原子拒绝，直到未来另行设计“带内容容器整体迁移”；
- 移动或合并成功后，只接受 P2/P1 返回的权威 Projection；失败、取消、Stale 或无效 Drop 不得乐观改动 UI。

### 4.2 装备栏位

只有装备栏位拥有物品类别和单槽互斥条款：

| 装备栏位 | 容量 | 可接受类型 |
|---|---:|---|
| 兵器 | 1 | 兵器 |
| 道袍 | 1 | 道袍/护甲 |
| 饰品 I、饰品 II | 各 1 | 饰品 |
| 空间戒指 | 1 | 空间戒指 |

装备栏位必须拒绝不兼容物品。向已占用且兼容的装备栏位拖拽时，必须由 P2/P1 以单一原子 Replacement/Swap 裁决；不可拆成两个本地 Move。

空间储物囊不是“快捷空间”装备，不能伪装成空间戒指放入空间戒指栏。它是带内部容器的普通空间物品，可进入任一普通储物位置；其访问方式见第 5 节。

### 4.3 用户操作入口

P4x 采用“拖拽负责物品位置变化”的规则：

- 普通格之间的 Move、Swap、Merge、Replacement 和从装备栏移出的 Unequip 必须通过真实拖拽的明确目标完成；
- 不新增，也不保留可用的 Move、Merge、Swap、QuickMove 或“放回”按钮；
- 双击、右键菜单和详情页不得再触发自动搬运或自动合并；若保留右键入口，只可用于查看详情或条件式显示装备/卸下状态，不得隐式提交物品位置事务；
- 现有 QuickMove 规划/Controller 可以作为非 UI 的历史内部能力保留以避免无关重构，但不得有任何真实用户输入入口调用它；
- 现有 Split 可以保留为明确的数量拆分流程，但拆分后的物品位置转移必须继续由拖拽完成；不得把 Split 菜单改造成 Move、Merge 或放回的替代按钮；
- 物品详情、选择、高亮、错误反馈、取消、Esc、Close/Reopen 保留。

### 4.4 装备/卸下按钮的条件显示

详情或条件菜单只允许保留与当前装备状态一致的一个语义动作：

| 当前物品状态 | 显示 | 不显示 |
|---|---|---|
| 物品不在任一玩家装备栏位 | 装备 | 卸下 |
| 物品在玩家装备栏位 | 卸下 | 装备 |

“装备”只能用于兼容的装备定义；有唯一、明确空目标时，可通过既有 Equip 事务进入该装备栏。若存在多个候选饰品栏或已占用目标，UI 必须要求玩家直接把物品拖到明确装备栏位，不得猜测替换对象或静默移动另一件装备。

“卸下”不是“放回”按钮：它不得自动猜测仓库、基础格、快捷空间或储物囊目标，也不得直接提交一个无明确目标的 Move。它只能进入或引导同一真实拖拽操作；实际 Unequip 只在用户把已装备物品拖到明确、合法的普通储物目标并 Drop 时提交。

因此，不存在独立的“放回”按钮，也不存在把任意物品一键返回某个默认容器的隐式规则。

## 5. 两类空间容器的正式语义

P2 当前只以 Spatial.Pouch 演示一个空间道具。本任务必须把数据、Projection、UI 标签、Fixture 和测试明确区分为以下两类：

| 类型 | 物品位置与访问 | 容器语义 | 非本任务内容 |
|---|---|---|---|
| 空间戒指 | 仅可装备到空间戒指栏 | 装备后显示其关联的快捷空间；其内部格是普通储物格，但属于玩家可快速访问的空间区域 | 不绑定 1—9，不实现消耗或世界内使用 |
| 空间储物囊 | 可作为普通空间物品存放在普通储物位置 | 打开后显示其关联的非快捷内部储物；它不产生快捷空间、不获得热键或快捷使用语义 | 不实现包中包扩展、整体移动已装内容的囊或世界掉落 |

实现要求：

1. 每个空间戒指和空间储物囊实例都必须稳定关联自己的 Child ContainerId；内部物品仍为 P1 Repository 中唯一实例；
2. 空间戒指装备前不得显示/提供快捷空间内容；装备后必须显示正确的快捷空间容量、稳定格位与内容；
3. 空间储物囊无论位于仓库、基础格、快捷空间或另一个允许的普通位置，打开时都明确标记为“非快捷储物囊”，不可被 UI、QuickMove 或热键误识别为快捷空间；
4. 从两类内部容器向任何普通目标拖拽、以及向其内部容器拖拽，都走同一 P4 → P3 → P2 → P1 链；
5. 空间戒指只能通过兼容装备栏的 Equip/拖拽进入空间戒指栏；空间储物囊不获得该装备栏权限；
6. 不复制内部物品到装备本体、玩家数组、快捷栏或 UI 本地数组。
